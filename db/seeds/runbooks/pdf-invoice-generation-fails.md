## General guidance

PDF invoices are generated by a background worker using Prawn. The
worker can fail when the invoice contains an unusually long line item
description (Prawn wrap failures) or when the DfE branding assets are
missing from the container after a deploy.

## Pre-requisites

- Access to the `@ghbfs-tech` GitHub team
- Cloud Foundry CLI logged in to production
- The `invoice_id` from the failing download attempt (visible in the URL)

## Steps

### 1. Retrieve the failing invoice details

```
cf run-task ghbfs-web "rails invoices:show[<invoice_id>]"
```

Note any unusually long strings in the output (over 200 chars per
line item).

### 2. Check the PDF worker health

```
cf app pdf-worker
cf logs pdf-worker --recent | grep -i error
```

If the worker is restarting or CPU-thrashing, restage it:

```
cf restage pdf-worker
```

### 3. Verify branding assets are present

```
cf ssh pdf-worker -c "ls -la /app/vendor/branding/"
```

Expected files: `dfe-crest.png`, `ogl-logo.png`. If either is missing,
redeploy the worker rather than uploading manually — the missing
files indicate an incomplete deploy.

### 4. Retry the invoice generation

```
cf run-task pdf-worker "rails invoices:regenerate[<invoice_id>]"
```

## Verification

Ask the school to reload the "Download invoice PDF" page. The download
should complete within 10 seconds. Confirm the PDF opens correctly
with DfE branding.

## Escalation

If the invoice has line items over 200 characters that cannot be
truncated (e.g. a legally binding description), escalate to
`@ghbfs-tech` for a code fix — Prawn needs a `long_string_break` mode
enabled for these edge cases.
